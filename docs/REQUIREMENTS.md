# 会話テーマ判定アプリ 要件定義書

## 1. 文書の目的

本書は、マイクから取得した日本語の会話を文字起こしし、Jevで一定時間ごとにテーマ分類するWindowsデスクトップアプリケーションの要件を定義する。

本書で定めるのは、アプリケーションが満たすべき目的、機能、画面、データ保持、および対象外の範囲である。保存形式、クラス構成、ライブラリ選定、API呼び出し方式などの詳細設計は対象としない。

## 2. 目的

利用者が会話中の現在テーマと、直近7日間に分類されたテーマの傾向をGUIで簡単に確認できるようにする。

処理の全体像は次のとおりとする。

```text
選択したマイク
      ↓
日本語の文字起こし
      ↓
現在の5分間だけ一時保持
      ↓
分類条件の確認
      ↓
Jevによるテーマ分類
      ↓
現在テーマ・7日間統計をGUIへ表示
```

## 3. 基本方針

- 会話テーマの判定と可視化という単一目的に集中する。
- シンプルな設計と必要最小限の機能を優先する。
- Jevは、定義済みテーマから会話の中心テーマを1つ選ぶために使用する。
- 文字起こし本文は永続保存しない。
- VRChatのChatBoxへの送信は行わない。
- 個人利用を想定する。

## 4. 対象環境

| 項目 | 要件 |
|---|---|
| 対象OS | Windows |
| 開発言語 | C# |
| GUI | WPF |
| 音声認識 | Windows AI Speech |
| 音声認識言語 | 日本語固定 |
| テーマ分類 | Jev |

## 5. 機能要件

### 5.1 開始と停止

- 利用者はメイン画面から文字起こしと分類処理を開始できること。
- 利用者はメイン画面から実行中の処理を停止できること。
- 開始後、5分に満たない状態で停止した場合、その時点の未分類の文字起こしを破棄すること。
- 停止時に残った5分未満の文字起こしを分類しないこと。

### 5.2 マイク入力と文字起こし

- 設定画面で使用するマイクを選択できること。
- 選択したマイクを次回起動時に復元できること。
- 選択したマイクの音声を日本語として文字起こしすること。
- メイン画面には、現在の5分間に得られた文字起こしだけを表示すること。
- 5分間の区切りを越えた文字起こしを次の分類区間へ持ち越さないこと。
- 文字起こし本文をファイルなどへ永続保存しないこと。

### 5.3 分類の実行条件

- 分類判定は5分ごとに行うこと。
- 分類対象は、その判定時点までの直近5分間に得られた文字起こしだけとすること。
- 次の両方を満たした場合に限り、Jevによる分類を実行すること。
  - 文字起こしが50文字以上である。
  - 発話が2回以上ある。
- 条件を満たさない5分間は分類結果を作成・保存しないこと。
- 条件を満たさない場合、現在テーマを変更しないこと。

### 5.4 テーマ分類

Jevは会話全体の中心テーマを判断し、次の8テーマから1つを選択すること。

| テーマ | 対象範囲 |
|---|---|
| VRChat | VRChatそのもの、ワールド、VRChat上の出来事 |
| 改変 | VRChatアバターの改変、衣装、Unity上でのアバター編集 |
| ゲーム | VRChat以外を含むゲーム全般 |
| 仕事 | 業務、職場、仕事上の話 |
| 雑談 | 他のテーマが中心ではない一般会話 |
| 恋バナ | 恋愛、好意、交際などの話 |
| 生活 | 食事、買い物、家事、健康などの日常生活 |
| その他 | 他のテーマに該当しない会話、または分類の確信度が基準未満の会話 |

- 複数テーマに関係する会話では、固定の優先順位を設けず、Jevが中心テーマを1つ選択すること。
- Jevが返したテーマの確信度が30%以上の場合、そのテーマを採用すること。
- 確信度が30%未満の場合、テーマを「その他」とすること。
- 確信度30%は採用範囲に含むこと。

### 5.5 現在テーマ

- アプリケーション起動時の現在テーマは空文字とすること。
- 分類が成立した場合、採用したテーマで現在テーマを更新すること。
- 発話量が分類条件を満たさない場合、直前の現在テーマを維持すること。
- Jevとの通信に失敗した場合、直前の現在テーマを維持すること。

### 5.6 通信エラー

- Jevとの通信に失敗した場合、GUI上に「通信エラー」を現在テーマとは別に表示すること。
- 通信に失敗した区間について、分類結果を作成・保存しないこと。

### 5.7 分類結果の保存

- 分類が成立した結果について、少なくとも分類日時とテーマを保存すること。
- 分類結果を自動削除しないこと。
- 初期段階では、分類結果をプロジェクト配下に保存すること。
- 保存済みの分類結果を、直近7日間の統計表示に利用できること。

### 5.8 設定

設定画面では、次の項目を変更できること。

| 設定項目 | 要件 |
|---|---|
| Jev APIキー | GUIから設定でき、次回起動時に復元できること |
| 使用マイク | GUIから選択でき、次回起動時に復元できること |

- 初期段階では、設定情報をプロジェクト配下に保存すること。

## 6. 統計要件

- 統計対象期間は、当日を含む7暦日とすること。
- 「直近168時間」ではなく、当日と過去6日の日付単位で集計すること。
- 統計対象期間内のテーマ別分類割合を円グラフで表示すること。
- 統計対象期間内の総分類数を表示すること。
- 分類条件を満たさなかった区間と、通信エラーになった区間を総分類数に含めないこと。

例として、9月20日時点の統計対象日は9月14日から9月20日までとする。

## 7. 画面要件

### 7.1 メイン画面

```text
┌────────────────────────────────────────┐
│               現在のテーマ             │
│                                        │
├──────────────────┬─────────────────────┤
│                  │                     │
│ 最近の文字起こし │ 過去7日間の円グラフ │
│                  │ 総分類数            │
│                  │                     │
├──────────────────┴─────────────────────┤
│ 設定                         開始  停止 │
└────────────────────────────────────────┘
```

- 画面上部の横幅全体を使って現在テーマを表示すること。
- 画面左側に、現在の5分間の文字起こしを表示すること。
- 画面右側に、過去7日間のテーマ別分類割合を示す円グラフと総分類数を表示すること。
- 画面左下に、設定画面を開くボタンを配置すること。
- 画面右下に、開始ボタンと停止ボタンを配置すること。
- 通信エラーは現在テーマとは別の状態として利用者が認識できるように表示すること。

### 7.2 設定画面

- Jev APIキーを入力・変更できること。
- 使用可能なマイクから、文字起こしに使用するマイクを選択できること。

## 8. データ保持要件

| データ | 永続保存 | 保存期間 | 用途 |
|---|:---:|---|---|
| 文字起こし本文 | しない | 現在の5分間だけ | 画面表示、テーマ分類 |
| 分類結果 | する | 自動削除しない | 現在テーマ更新、7日間統計 |
| Jev APIキー | する | 設定変更まで | Jevとの通信 |
| 選択したマイク | する | 設定変更まで | 次回起動時の復元 |

## 9. 対象外

本アプリケーションでは、次の機能を対象外とする。

- VRChat ChatBoxへの送信
- 文字起こし本文の履歴保存・閲覧
- 音声認識言語の切り替えまたは自動判定
- 複数テーマの同時採用
- 分類結果の自動削除
- 5分未満で停止した区間の分類
- 詳細な実装方式、保存形式、クラス構成、利用ライブラリの確定

## 10. 受け入れ条件

次の条件をすべて満たしたとき、本書に定めた要件を満たすものとする。

1. 設定したマイクから日本語の文字起こしを開始・停止できる。
2. 現在の5分間の文字起こしだけがメイン画面に表示され、永続保存されない。
3. 5分間に50文字以上かつ2発話以上ある場合だけ、Jevによる分類が行われる。
4. Jevの確信度が30%以上なら選択テーマ、30%未満なら「その他」が採用される。
5. 分類条件を満たさない場合と通信エラー時には、現在テーマが維持される。
6. 通信エラー時には、現在テーマとは別に「通信エラー」が表示される。
7. 成立した分類結果が保存され、当日を含む7日間の割合と総分類数が表示される。
8. 開始後5分未満で停止した文字起こしが分類されず、破棄される。
9. Jev APIキーと使用マイクが設定でき、次回起動時に復元される。
10. VRChat ChatBoxへの送信が行われない。

## 11. 詳細設計へ持ち越す事項

次の事項は要件では固定せず、詳細設計時に決定する。

- 設定情報と分類結果の具体的なファイル形式
- プロジェクト配下での具体的な保存先
- APIキーの保護方法
- 「発話1回」を数える具体的な判定方法
- 文字数の数え方
- 5分間の区切りを管理する具体的な方法
- Jevとの通信プロトコルおよび応答形式
- 使用するグラフ描画ライブラリ
- 通信エラーの解除・再試行・表示消去の具体的な挙動
- マイクが利用不能になった場合の処理
